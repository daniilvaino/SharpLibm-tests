# Точность исходных libm — сырые данные

Источник: P. Zimmermann и др., «Accuracy of Mathematical Functions in Single, Double, Double Extended, and Quadruple Precision», редакция **август 2026** — https://members.loria.fr/PZimmermann/papers/accuracy.pdf (HAL: https://inria.hal.science/hal-03141101 — закрыт анти-бот-защитой при моём обращении).

Версии библиотек в этой редакции: GNU libc 2.44, Intel Math Library 2026.1.0, AMD LibM 5.3, Newlib 4.6.0, OpenLibm 0.8.7, Musl 1.2.6, Apple 26.5.2, LLVM libc 22.1.8, MSVC (Visual Studio 2026), FreeBSD 15.1, ArmPL 26.07, CUDA 13.3.1, ROCm 7.2.4.

Порядок столбцов: GNU libc, IML, AMD, Newlib, OpenLibm, Musl, Apple, LLVM, MSVC, FreeBSD, ArmPL, CUDA, ROCm.

Метод (со слов статьи): binary32, функции одной переменной — полный перебор всех входов (значения точные); binary64 и функции двух переменных — «чёрный ящик» с рекурсивным дроблением интервала и случайными точками, не менее 10^6 выборок на порог; это нижние границы наибольшей ошибки. Эталон — GNU MPFR. Ошибка — |y − z| в ulp(z); для субнормальных — наименьшее положительное субнормальное. Если ровно один из результатов NaN — ошибка бесконечна (Inf).

Данные и программы поиска: https://gitlab.inria.fr/zimmerma/math_accuracy ; худшие случаи Лефевра: https://www.vinc17.net/research/testlibm/ ; таблицы 2 и 4–19 статьи перечисляют входы наихудших случаев по библиотекам.

### Восстановление пропусков (моё)
- Строки из 13 значений однозначны.
- sin/cos/tan (12): пропуск — ArmPL (подтверждено: в табл. 10 статьи у ArmPL этих функций нет).
- sqrt (12): пропуск — ArmPL (сказано в статье).
- acosh/asinh/atanh/cosh/sinh/tanh/erf/erfc (12): пропуск — LLVM libc. Основание: при таком выравнивании FreeBSD совпадает с OpenLibm во всех этих строках (как и во всех 13-значных), а при любом другом — нет; статья прямо не называет пустой столбец.
- hypot (12): пропуск — ArmPL (по аналогии с sin/cos/tan; LLVM = 0.500 как обычно). Не подтверждено текстом.
- exp10 (10): пропуски — OpenLibm, MSVC, FreeBSD (у них нет exp10); Musl = 4.14.
- j0/j1/y0/y1/lgamma/tgamma (10): пропуски — AMD, LLVM, ArmPL. Согласуется с фразами статьи: «lgamma — большие ошибки везде, кроме GNU libc и IML», «tgamma — большие ошибки у Newlib, OpenLibm, Apple, MSVC, FreeBSD».

### Аномалии, объяснённые в статье
- Musl acosh = Inf: «For x = -0x1.34e729fd08086p+21, Musl acosh yields 0x1.075fa39542c7fp+3 instead of NaN».
- LLVM libc pow = Inf: возвращает −∞ вместо +∞ при x = 0x1.b4234939ab74ap+997, y = 0x1.59ccddd614389p+62.
- pow = 636 ulp у OpenLibm и FreeBSD: вход x = 0x1.000002c5e2e99p+0, y = 0x1.c9eee35374af6p+31 (статья не объясняет причину).
- AMD LibM sin/cos = 10.1 ulp: cos при 0x1.9eb7148f354d6p+20, sin при 0x1.9eb7148f354d6p+21 (без объяснения).
- GNU libc sinh = 1.94e19: «a bug in the integration from the CORE-MATH code in GNU libc 2.44».
- «In double precision, GNU libc is the only library that provides all C23 functions».
